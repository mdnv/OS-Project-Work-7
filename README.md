# Практическая работа № 7 — Межпроцессное взаимодействие (IPC), вариант B

**Платформа:** Ubuntu Server 24.04.5 в VirtualBox (MacBook Air M1 подключается по SSH). **Язык:** Python 3.12+, стандартная библиотека, без сторонних зависимостей.

## Цель
1. Клиент–сервер на двух именованных каналах FIFO, клиенты по очереди.
2. Тот же сервис через Unix-domain сокет `socket.AF_UNIX`, отдельный процесс на каждого клиента.
3. Передача **10⁷ целых int32** (40 000 000 байт) через `multiprocessing.shared_memory` и через `multiprocessing.Pipe`; контроль CRC32 и сравнение времени.
4. Таблица сравнений — в `RESULTS.md`, численные результаты бенчмарка — в `benchmark_results.csv` после выполнения.

## Требования
- `python3 --version` — Python 3.8+ (на Ubuntu 24.04 обычно 3.12).
- Установленная Ubuntu, два SSH-терминала.
- Для бенчмарка нужно примерно **40 MB свободного `/dev/shm`**, а также свободная оперативная память. Проверить: `df -h /dev/shm` и `free -h`.

## 1. FIFO: ДВА SSH-терминала

**Терминал №1 (сервер):**

```bash
cd ~/OS-Practice-7
python3 fifo_server.py
```

Ожидаемый вывод: `FIFO-сервер запущен. Ожидаю клиентов по одному...`.

**Терминал №2 (клиент):**

```bash
cd ~/OS-Practice-7
python3 fifo_client.py "(12 + 8) * 3"
python3 fifo_client.py "100 / 4"
python3 fifo_client.py "2**8"
```

Результаты: `60`, `25.0`, `256`. Клиентов запускать **строго по очереди** (общие каналы ответов). После завершения — `Ctrl+C` в терминале №1; файлы `requests.fifo` и `responses.fifo` удаляются.

## 2. Unix-сокет: ДВА SSH-терминала

**Терминал №1 (сервер):**

```bash
cd ~/OS-Practice-7
python3 unix_server.py
```

**Терминал №2 (клиенты):**

```bash
cd ~/OS-Practice-7
python3 unix_client.py "(12 + 8) * 3"
python3 unix_client.py --demo
```

`--demo` одновременно запускает шесть **отдельных клиентских процессов**. Сервер порождает **отдельный серверный процесс** для каждого подключения; он выводит их PID. По завершении в терминале №1 нажать `Ctrl+C`, файл `calculator.sock` удаляется.

## 3. SharedMemory против Pipe

Сервер не нужен: из любого SSH-терминала выполнить:

```bash
cd ~/OS-Practice-7
python3 benchmark.py
cat benchmark_results.csv
```

По умолчанию берём **10 000 000** чисел, размер `array('i')` — **40 000 000 байт**, 3 повтора каждого механизма, выводится медиана времени. `CRC32 OK` подтверждает целостность полученных данных. Для быстрой предварительной проверки:

```bash
python3 benchmark.py --count 100000 --repeat 1
```

**Внимание:** быстрый прогон перезапишет CSV! **После теста обязательно выполнить `python3 benchmark.py` без параметров**, чтобы итоговый CSV отражал нужные 10⁷ элементов.

Сравнение измеряет передачу и проверку CRC32, но исключает создание исходного массива и запуск процессов. SharedMemory: запись в общий сегмент + уведомление через `Event` + CRC32 получателя. Pipe: передача 40 MB блоками 1 MiB + CRC32 получателя. Время зависит от параметров виртуальной машины.

## 4. Проверка очистки

```bash
cd ~/OS-Practice-7
ls -l *.fifo *.sock 2>/dev/null || echo "FIFO и сокетов нет"
ls /dev/shm | grep '^os_pr7_' || echo "Сегментов работы №7 нет"
```

После штатного завершения серверов и бенчмарка ожидаются две строки `... нет`. Другие файлы в `/dev/shm` не удалять.

После аварийного завершения **убедитесь, что соответствующий сервер не работает**, затем можно очистить наши FIFO/сокет:

```bash
rm -f ~/OS-Practice-7/requests.fifo ~/OS-Practice-7/responses.fifo ~/OS-Practice-7/calculator.sock
```

Если сегмент `os_pr7_*` остался после аварийного завершения и ни одна программа его не использует, удаляйте **только собственное** имя сегмента, а не весь `/dev/shm`.

## Основные ошибки

| Проблема | Что делать |
|---|---|
| Клиент FIFO «завис» | Проверьте сервер в **другом** терминале. Именованные каналы блокируются при открытии, пока второй участник не подключился. Не запускайте одновременно нескольких FIFO-клиентов. |
| `No such file or directory` на сокете | Сначала запустите `python3 unix_server.py`. |
| `Address already in use` | Завершите предыдущий сервер, проверьте файл `calculator.sock`; при необходимости удалите только stale-сокет. |
| `Bus error`, нехватка памяти | Проверьте `df -h /dev/shm` и `free -h`. Увеличьте RAM для Ubuntu VM или проверьте малым запуском `--count 100000`. Для сдачи повторите на 10⁷. |
| `Permission denied` | Убедитесь, что работаете в своей папке `~/OS-Practice-7`. Для Python не нужен `sudo`. |
| `ModuleNotFoundError` | Запускайте из папки проекта, чтобы `calculator.py` был рядом. Ничего устанавливать через pip не требуется. |

## Ответы на вопросы

1. **SharedMemory обычно быстрее**, потому что адресное пространство двух процессов отображается на общий участок памяти и не нужно передавать весь массив через канал. **Опасна**, поскольку одновременный доступ без `Lock`/`Event` приводит к race condition: чтению незаписанных или частично обновлённых данных. Здесь применён `Event`.
2. Если у pipe закрыты все читающие концы, Linux отправит писателю `SIGPIPE` (по умолчанию процесс завершается). Если сигнал игнорируется, операция записи возвращает `EPIPE` — в Python `BrokenPipeError`.
