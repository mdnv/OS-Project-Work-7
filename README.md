# Практическая работа №7 — Межпроцессное взаимодействие (IPC)

**Вариант B** · **Python 3** · **Ubuntu Server 24.04.5 (VirtualBox, SSH)**

## Цель
Реализовать IPC через именованные каналы FIFO, Unix-сокеты, SharedMemory и Pipe, сравнить время передачи данных и проверить очистку ресурсов.

## Что сделано
- **FIFO:** `fifo_server.py`, `fifo_client.py` — вычисление выражений, запросы и ответы через два FIFO, клиенты по очереди.
- **Unix-сокеты:** `unix_server.py`, `unix_client.py` — `AF_UNIX`, отдельный процесс на каждого клиента; 6 клиентов одновременно.
- **SharedMemory / Pipe:** `benchmark.py` — передача **10⁷ чисел (40 MB)**, 3 запуска, медиана времени и проверка CRC32.
- **Отчёт:** `RESULTS.md`, `benchmark_results.csv`.

## Запуск
Откройте **два SSH-терминала** Ubuntu и в каждом выполните `cd ~/OS-Practice-7`.

**1. FIFO** — терминал 1:
```bash
python3 fifo_server.py
```
Терминал 2 (запросы по очереди):
```bash
python3 fifo_client.py "(12 + 8) * 3"
python3 fifo_client.py "100 / 4"
```
Ответы: `60`, `25.0`. Остановить сервер: `Ctrl+C`.

**2. Unix-сокеты** — терминал 1:
```bash
python3 unix_server.py
```
Терминал 2:
```bash
python3 unix_client.py "2**8"
python3 unix_client.py --demo
```
Ответ: `256`; `--demo` запускает 6 одновременных клиентов. Остановить сервер: `Ctrl+C`.

**3. Сравнение SharedMemory и Pipe:**
```bash
python3 benchmark.py
cat benchmark_results.csv
```
Проверка `CRC32 OK` подтверждает целостность данных. Время зависит от мощности виртуальной машины.

**4. Проверка очистки** (после остановки серверов):
```bash
ls -l *.fifo *.sock 2>/dev/null || echo "FIFO и сокетов нет"
ls /dev/shm | grep '^os_pr7_' || echo "Сегментов работы №7 нет"
ipcs -q
```
После завершения не должно оставаться ресурсов этой работы; очереди System V программой не создаются.

## Вывод
FIFO удобен для последовательного обмена, Unix-сокеты поддерживают одновременных клиентов. SharedMemory обычно быстрее при больших объёмах, но требует синхронизации (`Event`); Pipe передаёт поток байтов без общей памяти. Фактические замеры записаны в `RESULTS.md`.

## Контрольные вопросы
**1. Почему разделяемая память — самый быстрый и самый опасный механизм IPC?**  
Процессы работают с одним участком памяти без пересылки всего массива через канал. Но без синхронизации возможны состояние гонки, чтение неготовых данных и ошибки. Используют `Event`, `Lock` и другие средства синхронизации.

**2. Что произойдёт при записи в pipe, у которого закрыты все читающие концы?**  
В Linux процесс получит `SIGPIPE` (обычно завершится). Если этот сигнал игнорируется, запись завершится ошибкой `EPIPE`, в Python — `BrokenPipeError`.
